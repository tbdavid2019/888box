## Design Specificity Verdict

### LLM Assessment (設計專屬性評定)
目前 888box 在頂部導覽列上處於「**外觀現代、但幾何骨架分裂**」的狀態。
系統原本擁有不錯的深色玻璃擬態（Glassmorphism）與漸層質感，但前後台在導覽架構上被拆成了三座孤島：
1. **前台上傳中心 (`renderSiteHeader`)**：採用 Pill 藥丸按鈕與純文字 Tab，並使用了破壞性的 `width: 100vw; margin-left: calc(50% - 50vw); margin-top: -20px;` CSS 駭客，導致桌面瀏覽器出現橫向滾動條晃動。
2. **後台管理系統 (`renderAdminHeader`)**：採用 Rounded 8px 圓角與帶 Lucide Icon 的 Tab，並在右側拆分成「頁面操作」與「全域工具」雙層架構，但外層依舊繼承了前台的 `box-site-header`，造成尺寸與 `!important` 覆蓋混亂。
3. **公開分享頁面 (`view.php`)**：完全獨立手寫了 `.asset-header-top`，使用固定定位（Fixed）配合 `margin-top: 88px/76px` 的 Magic Numbers 來避讓，甚至重複實作了第三套語言切換按鈕。

### Deterministic Scan (自動化檢測)
- 透過 `impeccable detect` 靜態掃描：PHP 樣板整體無語法結構崩壞，在 `upload_image.php:292` 檢測出 `broken-image` 預覽空白屬性警告。
- 程式碼審查（Codex & OpenCode 聯合審查）：確認 CSS 存在多處重複樣式覆蓋、未統一的圓角與高度 Token、以及 4 個不同的響應式斷點。

## Overall Impression (整體直覺印象)
個別按鈕與磨砂玻璃的視覺質素合格，但**幾何對齊與版面律動完全脫節**。
最致命的是：當使用者在「圖片 → 影片 → 音訊 → 文件」之間切換時，中間的導覽列會因為左側字串長度與右側按鈕數量的不同而「**左右橫向跳動（Jitter）**」，給人粗糙拼湊的廉價感；加上 Windows 或外接螢幕常駐滾動條時的水平捲動溢出，嚴重拉低了整體工藝水準。

## What's Working (值得保留的優點)
1. **後台操作區的二元分層（Two-Tier Actions）**：將「當前頁專屬操作（如：多選模式、新增帳號）」與「全域系統工具（語言、設定、首頁、登出）」以分隔線區隔，資訊架構非常清晰。
2. **暗色主題色彩 Tokens**：深藍黑底色（`#161a2b`）搭配柔和紫藍 Accent（`#7aa2f7`、`#7dcfff`）視覺舒適，高亮對比度足夠。
3. **無縫中英切換（i18n）機制**：無論前後台均已內嵌 `renderLanguageSwitcher`，能即時同步偏好語言。

## Priority Issues (優先修復問題)

### [P0] 結構性 CSS 駭客：`100vw` 造成全域水平溢位與滾動條抖動
- **Why it matters**: `config/theme_helper.php` 為了強行撐滿螢幕，使用了 `width: 100vw; margin-left: calc(50% - 50vw); margin-top: -20px;`。在桌面具備常駐滾動條的環境下，`100vw` 會包含滾動條寬度（15-17px），造成整個頁面產生惱人的左右橫向滾動；負 margin 亦與 `login-container` 等內容間距嚴重耦合。
- **Fix**: 移除 `100vw` 與 `calc(50% - 50vw)`。若需滿版，應由最外層 Shell 或 `<header>` 直接設定 `width: 100%; box-sizing: border-box;`，頁面內容容器自帶 padding 或 gutter。
- **Suggested command**: `/impeccable layout`

### [P1] 導覽列「水平飄移（Wandering Alignment）」與重複麵包屑資訊
- **Why it matters**: 
  1. `box-site-header` 使用 `flex: 1` 讓中間導覽置中，但因為左側（品牌+文字）與右側（操作按鈕）寬度在不同頁面不對稱，導致中間頁簽實際上只是在「剩餘剩餘空間」置中，而不是在「螢幕絕對中心」，切換分頁時會明顯左右晃動。
  2. 左側已經有「888 BOX / 圖片」，中間頁簽又高亮了「圖片」，在 100px 範圍內重複兩次相同資訊，產生視覺雜訊。
- **Fix**: 
  1. 改用 CSS Grid 三欄排版：`grid-template-columns: minmax(0, 1fr) auto minmax(0, 1fr);`，確保中間導覽永久鎖定在 Viewport 幾何正中心。
  2. 前台左側簡化為乾淨的 `888 BOX` 品牌原點，讓中間 Active Tab 承載當前位置的唯一責任。
- **Suggested command**: `/impeccable distill`

### [P1] 三套平行 Header 實作與元件尺寸漂移（Token Drift）
- **Why it matters**: 
  - 前台（`renderSiteHeader`）、後台（`renderAdminHeader`）、分享頁（`view.php`）三者各自為政。
  - 按鈕高度混雜：前台分類 32px、前台按鈕 36px、後台分類 34px、後台按鈕 34px、後台工具 32px、語言按鈕 30px。
  - 圓角混雜：前台藥丸（999px）混搭矩形（7px），後台統一（8px），分享頁又全變藥丸。
- **Fix**: 在 `:root` 定義全域統一的導覽規格變數：
  `--nav-height: 60px; --nav-item-height: 34px; --nav-radius: 8px; --nav-pill-radius: 999px;`，統一前後台按鈕高度與間距律動。
- **Suggested command**: `/impeccable extract`

### [P2] 響應式斷點割裂與手機版認知負載升高
- **Why it matters**:
  - 前台斷點在 640px，後台斷點在 768px 與 960px，分享頁斷點在 680px。
  - 後台在 960px 直接拔掉文字標籤，變成「純圖示」，使用者難以辨識；前台在 640px 則將頁簽折行成多列，吃掉手機大量垂直視野。
- **Fix**: 統一響應式斷點（Mobile ≤768px, Tablet ≤1024px）。手機版一律採用單列水平滑動（`overflow-x: auto; scrollbar-width: none;`），並保留可辨識的微型文字或標準漢堡選單。
- **Suggested command**: `/impeccable adapt`

### [P2] 遺留 CSS（Legacy Cruft）與 Focus-Visible 可訪問性缺失
- **Why it matters**: `static/css/admin/shared.css` 開頭保留了大量舊有的 `.admin-header`, `.admin-tabs`, `.admin-actions` 規則，與新版的 `.box-admin-*` 造成命名衝突；且暗色介面在鍵盤 Tab 巡覽時缺乏高對比的 `focus-visible` 外框。
- **Fix**: 清理 legacy `.admin-header` 區塊；為所有導覽與動作按鈕補上 `outline: 2px solid #7dcfff; outline-offset: 2px;`。
- **Suggested command**: `/impeccable polish`

## Persona Red Flags (使用者畫像警訊)

### 1. Alex (Impatient Power User / 效率型資深管理員)
- **警訊**：切換不同分頁時，按鈕位置因為 Header 的漂移而跳動，無法形成肌肉記憶（Muscle Memory）；且完全沒有鍵盤快捷鍵（如 `1-4` 切換分類、`Esc` 退出、`Ctrl+K` 搜尋）。
- **後果**：操作流暢度受阻，頻繁在不同後台頁面尋找「設定」與「登出」按鈕。

### 2. Jordan (Confused First-Timer / 初次使用者)
- **警訊**：前台上傳頁左上角寫著「888 BOX / 圖片」，中間又選中「圖片」，讓使用者疑惑「/ 圖片」是不是一個可以點擊的返回上層連結；在分享頁又出現完全不同長相的 Header。
- **後果**：無法建立對平台階層與操作模式的信心。

### 3. Casey (Distracted Mobile User / 單手操作手機用戶)
- **警訊**：在手機上打開後台，頂部導覽直接被折成 3 列（Brand、Nav、Actions），佔用了螢幕三分之一的高度；右側的圖示沒有文字說明，不知道齒輪和房子代表什麼。
- **後果**：誤觸率高，閱讀與上傳有效工作區極度受限。

## Minor Observations (細微觀察)
1. `view.php` 的內容主體使用了 `margin-top: 88px` 與 `76px` 來硬避開固定頂部列，若螢幕寬度改變導致換行，內容會直接被 Header 遮擋。
2. 前台導覽列的 HTML 標籤寫著 `aria-label="管理分類"`，但這實際上是前台公眾上傳中心，建議調整為 `aria-label="資產類型導覽"`。
3. `admin/index.php` 頂部除了全域 Header 外，畫面上還有一個次級工具列，間距（`margin-top: 24px`）需要與其他後台頁面保持呼吸節奏一致。

## Questions to Consider (核心思考點)
- **為什麼前台與後台的頁簽外觀要故意分歧？**（前台是純文字膠囊，後台是圖示方塊——統一採用「Icon + Label」的標準語彙是否更專業且辨識度更高？）
- **前台左側真的需要顯示 `/ 圖片` 這種麵包屑嗎？**（中間導覽列的第一個 Tab 就是「圖片」且已是 Active 狀態，左側保留純粹的品牌 Logo 是否更俐落？）
- **分享頁（view.php）能否完全繼承全域 Header？**（只需要把中間的 Center Nav 隱藏，右側放置上傳按鈕與語言切換，就能消滅第三套代碼）
